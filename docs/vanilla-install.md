# Vanilla 下载与安装：Review 说明

目前可从 CLI 完成受支持原版的文件下载、原生库解压、资源映射及离线校验。
范围是 Minecraft Java 版客户端实例文件；Java 管理、登录、游戏启动和加载器仍为后续阶段。

## 运行与验收

沿用之前单文件测试的 Linux / x86_64 目标，可以运行：

```sh
.venv/bin/mcinst install 1.20.1 \
  --directory instances/vanilla-1.20.1-linux \
  --os linux --arch x86_64 --os-version 6.0 \
  --source official

.venv/bin/mcinst verify instances/vanilla-1.20.1-linux
```

这会下载 Linux 目标的完整原版文件；在 macOS 上运行命令也不会把它自动改为 macOS 实例。
为本机安装时可省略平台参数，使用本机 OS / 架构；也可以显式选择 osx / arm64 等目标。
旧式原生库没有声明 ARM64 支持时，规划器会明确拒绝，不自动替换目标或 Java。

`--source auto` 为 BMCLAPI 优先、官方回退。若 BMCLAPI 不稳定，可先使用 official。
`--concurrency` 默认 8，`--per-source` 默认 4，两者均限定为 1～64。
单文件重试或回退不会增加并发上限，退避等待期间释放来源配额。
同一来源的 CDN 重定向仍计入原逻辑来源的配额。

同一命令重跑将校验并复用已完成文件，并重新生成或修复派生文件。
删掉一个受管理库文件或损坏一个资源映射后，可以先 verify，再重跑 install 验证修复。
版本、平台及功能条件必须与原实例相同；不同配置应使用新的实例目录。
可更换 --source，不改变固定计划中的版本、目标路径或哈希。

`install --json` 向 stdout 输出成功结果，阶段与进度写入 stderr。
`verify --json` 输出状态、缺失文件、不匹配文件、缺少预期哈希的文件及 ok。
verify 不联网、不修复、不改写游戏文件，异常或未完成状态返回非零退出码。
没有预期哈希的旧库只能检查上游已提供的信息，仍会明确列为 unverified。

## Review 入口

| 文件 | 职责 |
| --- | --- |
| `downloads/limits.py` | 共享的每逻辑来源并发配额 |
| `downloads/scheduler.py` | 固定数量 worker、汇总进度、错误取消及输入顺序结果 |
| `installation/installer.py` | 计划、下载、后处理和状态提交的编排 |
| `installation/state.py` | 固定计划、安装记录、原子状态写入及实例进程锁 |
| `installation/postprocess.py` | 目标用途检查、受控 ZIP 解压及资源映射 |
| `installation/verify.py` | 受管理文件的离线校验 |
| `cli.py` | install / verify 命令及展示 |
| `tests/test_scheduler.py` | 并发上限、退避配额、失败取消 |
| `tests/test_installer.py` | 包含真实 ZIP 内容的合成端到端安装与恢复测试 |

## 实例布局

```text
instances/vanilla-1.20.1-linux/
    .mcinst.lock
    instance.json
    install-plan.json
    minecraft/
        versions/
        libraries/
        assets/
        resources/  (仅在资源索引要求时生成)
```

`.mcinst.lock` 是进程锁文件，安装结束也保留其 inode；锁随文件句柄关闭释放。
Windows 使用 msvcrt 字节锁，其他受支持桌面系统使用 flock。
不会因一次崩溃留下需要手动删除的“占用标记”；不同进程不能同时安装同一实例。
网络文件系统的锁行为没有实际验证，推荐使用本地目录。

`install-plan.json` 固定首次解析的全部文件和后处理声明。
`instance.json` 保存计划的 SHA-256、安装状态、此次已下载与复用数量、派生文件哈希和错误信息。
文件写入采用同目录临时文件、fsync、原子替换。计划文件校验不匹配或状态损坏时拒绝覆盖。
目标非空且没有本工具安装记录时也拒绝安装，避免混入已有启动器目录。

## 阶段、失败和恢复

首次安装流程：

1. 获得实例锁，检查目录和状态。
2. 获取、验证并保存固定安装计划。
3. 标记 installing，执行有界并发下载和文件校验。
4. 全部文件完成后解压旧式原生库，生成 virtual / resources 映射。
5. 保存派生文件的哈希和大小，标记 installed。

恢复时读取本地固定计划，不重新查询“最新版本”或重新解析上游列表。
版本 JSON、资源索引若尚未写入实例，仍会按已固定地址及哈希下载，不能把这当成重新规划。
完整且有预期哈希的文件不会再请求网络，损坏或缺失文件会重下。
未提供预期哈希的旧 Maven 库仍重新下载，避免仅凭大小误判内容身份。

任一下载失败会取消并等待其他 worker 完成清理，保留已提交且有效的文件。
普通失败记录为 failed，正常取消记录为 cancelled，不标记 installed。
磁盘故障若同时阻止错误状态保存，原异常会附加说明，原有状态文件通过原子写入保持完整。
首次保存计划与记录之间发生磁盘失败可能留下不完整元数据对，此时会明确拒绝自动继续。

当前恢复粒度为完整文件。单个文件中断时清理残片，Range 字节级续传尚未实现。
安装不是整个目录的原子事务：失败时可能已有完整文件或部分后处理产物，重跑可修复。
不会删除不在计划中的额外文件；saves、mods、config 等用户内容不属于下载或映射目标。

## 后处理与取消

旧式 natives 先在临时工作目录展开，校验所有成员后才逐文件发布到实例。
归档绝对路径、父目录跳转、反斜杠路径、Windows 盘符、符号链接及特殊文件均拒绝。
检查同名内容冲突、大小写冲突和文件/目录冲突；同名且内容一致的原生文件可复用。
跳过 META-INF 和元数据声明的排除前缀；限制原生库成员总数及总解压大小。
资源映射按源对象的预期哈希和大小复制，再原子提交。

后处理运行在线程中。取消时会等线程结束再释放实例锁，避免取消后的后台写入与恢复任务相撞。
由此取消大型后处理可能需要等待一小段时间；状态仍记录为取消而不是安装成功。
其他进程恶意替换目录树的竞态不在当前威胁模型中，实例目录应由调用者控制。

## 验证记录与支持边界

89 项离线测试通过，包含 CLI 完整安装、离线 verify、文件修复、取消恢复、来源切换、
任务并发上限、损坏 ZIP、路径穿越、符号链接、解压大小限制及实例锁。
Ruff 检查、格式检查及 git diff --check 通过。
合成端到端测试真实写入目录并展开 ZIP，但不等同于完整真实游戏版本的联网安装验收。
本会话网络限制仍在，完整真实源下载需在本机验收。
Python 3.12 最低版本、Windows 锁分支和跨平台实际游戏运行尚未验证。

原版支持范围继承规划器边界：独立原版、带 assetIndex 的资源布局及可解释的平台规则。
缺少资源索引的历史格式、继承版本及 JAR 重定向仍会报不支持。
“installed” 表示计划中的实例文件和后处理已完成，不表示 Java 已准备或游戏已经启动。
